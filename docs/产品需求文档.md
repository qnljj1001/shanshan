# 产品需求文档

## 1. 项目背景

个人学习、求职和日常工作中会产生大量文档，例如课程资料、招聘 JD、简历、学习笔记、会议记录。普通聊天模型无法稳定引用这些本地资料，因此需要一个支持文档上传、知识库问答、引用溯源和文档工具处理的 AI 助手。

---

## 2. 目标用户

第一阶段目标用户是项目作者本人。

核心场景：

- 学习资料问答。
- 招聘 JD 分析。
- 简历优化和面试准备。
- 文档总结。
- 待办提取。
- 周报生成。

第二阶段可扩展到小团队或企业内部知识库。

---

## 3. 项目目标

必须达到：

1. 能上传常见文档。
2. 能解析文档并建立知识库。
3. 能基于文档进行问答。
4. 回答必须带引用来源。
5. 文档中没有答案时能拒答。
6. 能通过浏览器使用。
7. 能通过 Docker Compose 启动。
8. 能部署到阿里云服务器。
9. 能作为秋招面试项目清楚讲解。

---

## 4. 非目标

第一阶段不做：

- 大模型训练。
- 大模型微调。
- 多租户 SaaS。
- 复杂权限系统。
- 移动端 App。
- Kubernetes 部署。
- 多 Agent 协作平台。
- 高并发商业化架构。

---

## 5. 核心功能

### 5.1 聊天

- 用户输入问题。
- 系统调用大模型生成回答。
- 支持流式输出。
- 支持 Markdown 展示。
- 保存会话历史。

验收：

- 页面可完成连续对话。
- 刷新页面后历史记录仍可查看。

---

### 5.2 文档管理

- 上传 PDF、Word、Markdown、TXT。
- 展示文档列表。
- 查看文档处理状态。
- 删除文档。

验收：

- 至少能上传并解析 5 份真实文档。
- 文档解析失败时有明确错误提示。

---

### 5.3 知识库问答

- 文档解析后切片。
- 生成 Embedding。
- 存入向量索引。
- 用户提问时检索相关 chunk。
- 大模型基于检索结果回答。
- 展示引用来源。

验收：

- 回答能命中文档内容。
- 引用来源可以定位到文档和片段。
- 对无依据问题能拒答。

---

### 5.4 文档工具

第一阶段工具：

- 文档总结。
- 待办提取。
- 周报生成。

验收：

- 工具输入和输出结构清晰。
- 工具调用过程有日志。
- 工具失败时能返回原因。

---

## 6. 成功标准

秋招前至少完成：

- 一个公开或可展示的 GitHub 仓库。
- 一个本地可运行版本。
- 一个 Docker Compose 可启动版本。
- 一个阿里云在线演示地址。
- 一份 README。
- 一份架构文档。
- 一份 RAG 评估文档。
- 一份部署文档。
- 一份面试讲解文档。
