# 部署指南

## 1. 部署原则

不要一开始就 Docker 化。

推荐顺序：

```text
本地源码启动成功
  -> 本地 Docker 启动成功
  -> 云服务器 Docker 启动成功
  -> Nginx 反向代理
```

---

## 2. 本地源码启动

后端：

```bash
cd backend
source .venv/bin/activate
uvicorn app.main:app --reload --port 8000
```

前端：

```bash
cd frontend
npm run dev
```

---

## 3. Docker 第一版目标

第一版 Docker 只打包后端。

原因：

- 先验证 Docker 基础概念。
- 避免前端、数据库、Nginx 一起引入导致排错困难。

第一版完成标准：

```bash
docker compose up --build
```

然后访问：

```text
http://127.0.0.1:8000/docs
```

---

## 4. 后续 Docker Compose 服务

最终服务：

```text
backend
frontend
database
vector-db
nginx
```

第一阶段可简化为：

```text
backend
frontend
nginx
```

SQLite 和 FAISS 可以先用 volume 挂载本地数据目录。

---

## 5. 环境变量

服务器上必须配置：

```text
OPENAI_BASE_URL
OPENAI_API_KEY
MODEL_NAME
EMBEDDING_MODEL_NAME
DATABASE_URL
UPLOAD_DIR
VECTOR_INDEX_DIR
```

注意：

- `.env` 不提交。
- `.env.example` 提交。
- 云服务器上的 `.env` 单独维护。

---

## 6. 阿里云部署检查清单

部署前：

- ECS 可以 SSH 登录。
- 安全组开放 80 端口。
- 安全组开放必要的后端测试端口，例如 8000。
- 已安装 Docker。
- 已安装 Docker Compose。
- 项目代码已拉取到服务器。
- `.env` 已配置。

部署中：

```bash
docker compose up --build -d
docker compose ps
docker compose logs
```

部署后：

- 浏览器能访问前端。
- `/api/health` 正常。
- 模型调用正常。
- 文档上传正常。
- 日志中没有持续报错。

---

## 7. Nginx 目标

Nginx 负责：

- 对外暴露 80 端口。
- 转发前端静态资源。
- 反向代理 `/api` 到后端。

示例转发关系：

```text
http://server/
  -> frontend

http://server/api/
  -> backend:8000
```

---

## 8. 常见问题

### 8.1 容器能启动，但模型调用失败

检查：

- `.env` 是否挂载。
- `OPENAI_BASE_URL` 是否正确。
- `OPENAI_API_KEY` 是否正确。
- 服务器能否访问中转接口。

---

### 8.2 本地可以，服务器不可以

检查：

- 服务器安全组。
- 防火墙。
- Docker 端口映射。
- Nginx 配置。
- 环境变量。

---

### 8.3 文件上传失败

检查：

- upload 目录是否存在。
- 容器 volume 是否挂载。
- 文件大小限制。
- 后端日志。
